# 推理成本断层（Inference Cost Gap）

> **状态：已确认，待修复。** 这是一份调研笔记，不是权威文档。
> 结论的记录在 [`ADR-0002`](../decisions/ADR-0002-semantic-extract-as-inference-cost.md)。
>
> 日期：2026-10-03
> 发现方式：读取 `internal/mining/` 源码时发现

---

## 一句话

**三个 executor 都不调用 LLM。挖矿不消耗任何推理额度,`TokensIn`/`TokensOut` 恒为 0。**

---

## 代码证据

```bash
$ rg -i 'openai|anthropic|llm|inference|completion' internal/mining/
loop.go:196  // providerOf ... defaulting to "local" for tasks that need no inference
loop.go:200  // compute tasks genuinely consume no inference budget

$ rg 'TokensIn|TokensOut' internal/mining/loop.go
# 无赋值处 —— 两个字段永远是零值
```

`work.Provider` 与 `work.Model` 的来源:

```go
Provider:   providerOf(spec),   // 从 spec 抄一个字符串
Model:      modelOf(spec),      // 同上
```

**是文本搬运,不是真实计量。**

### 三个 executor 实际做什么

| executor | 实现 | 用 LLM 吗 |
|---|---|---|
| `probe` | HTTP GET,读状态码 | ❌ |
| `extract` | HTTP GET + 硬编码 dot-path 提取 | ❌ |
| `compute` | sha256 / 字符串拼接 / JSON 键排序 | ❌ |

全部是**确定性的网络或 CPU 操作**。

---

## 为什么这是断层而不只是"少个 provider"

`MVP.md` §1.3 的核心洞察建立在"推理额度是稀缺资源"之上。剥掉推理后:

| §1.3 声称的性质 | 实际是否成立 |
|---|---|
| **稀缺**（rate limit 是硬上限） | ❌ 不成立 —— HTTP 请求没有这项限制 |
| **有真实成本**（想放量必须多买订阅） | ❌ 不成立 —— 放量的边际成本是带宽 |
| **可验证**（推理产出有 hash） | ✅ 仍成立（hash 的是结果,与是否用 LLM 无关） |
| **自限**（被自己的账单限制） | ❌ **不成立** |

**三行里三行失效。** 只有"可验证"活着 —— 因为它不依赖成本。

---

## 连锁后果:抗女巫的第一层被削弱

`MVP.md` §5.2 的抗女巫论证是**两层**:

| 层 | 机制 | 剥掉成本后 |
|---|---|---|
| **① 全局去重** | 同一 artifact 第二个提交者得 0 分 | ✅ 仍有效,但**只迫使换 URL** |
| **② 对抗验证** | 随机指派验证者重算 + 质押 | 未实现(S4);且验证者若也免费,质押无意义 |

**关键:** 去重把"重复同一 URL"这条路的收益归零,但**没有阻止换 URL**。

成本为零时,攻击者的最优策略是:

```text
开 N 个 agent → 每个抓 M 个不同 URL → N×M 份有效工作量
成本 ≈ 带宽 + CPU ≈ 0
收益 = 积分
```

**一个 curl 脚本就能刷满全网。**

### 为什么 §5.0 挡不住这个

`MVP.md` §5.0 **明确拒绝**过这类任务:

> ❌ `fetch + 任意 hash` —— 只证明"取过",**无 ground truth**

它之所以能被拒绝,是因为当时假设**推理质量是工作量的来源**。剥掉推理后,`probe` 与
`extract` 就退化成了被拒绝的那种任务 —— **只是多了一个字段名**。

**这不是代码 bug。代码写得对,§5.0 的逻辑也对。断层发生在两者之间:没有任何一层的
设计把"消耗推理"真正接进来。**

---

## 它不是"可选补全"

`TASKS.md` 把 `S2-6`(BYO API key)标为 `⬜ todo`,读起来像"少接一个 provider"。

**实际它是整个 play 的承重项。** 没有它:

- §1.3 的成本不存在 → 稀缺性不存在 → 自限不存在
- `MVP.md` §10.1 的核心叙事("你的 agent 订阅是矿机")**不成立**
- 社区/尽调里会出现一个无法回答的问题:

  > **"我明明没用我的 Codex 额度,凭什么说我在用它挖矿?"**

---

## 曾考虑的四个方案

| 选项 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 语义化 extract** | 保住 §5.0 的二值验证;成本真实;不新增任务类型 | 成本是**诱导**的,可被机械规则绕开 | ✅ **采用**(ADR-0002) |
| B. 改叙事为"数据采集网络",用押金/白名单做稀缺 | 不依赖 LLM | **放弃**"订阅挖矿"这个核心卖点;需重写 §1.3 与 §10.1 | 备选 |
| C. 只接 S2-6,任务不变 | 改动最小 | **不解决** —— 任务本身不需要推理,`TokensIn` 仍为 0 | 无效 |
| D. 引入生成类任务 + 验证层 | 成本最真实 | **破坏 §5.0**,必然引入争议层 → 复杂度爆炸 | 拒绝 |

选 A 的理由:它是**在不破坏二值验证的前提下**,唯一能让成本真实的方案。

---

## 采用方案后必须保留的诚实声明

语义化 extract 让"在陌生杂乱页面上解析自然语言字段"**经济上**需要 LLM。
但这是**经济诱导**,不是**协议强制**:

- 决心机械解析的攻击者**仍可写规则绕开** LLM(针对特定站点写正则)。
- 因此抗女巫的**主要承重**仍是**全局去重**(迫使不断更换 URL)。
- 语义化只**抬高**成本,并未**证明**成本。

> **不得对外表述为"不可绕过"。** 这与 `MVP.md` §5.6 对 sybil 防御的诚实要求一致:
> 把有洞的机制包装成无洞,被拆穿一次叙事就没了。
