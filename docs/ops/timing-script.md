# 判据 ①③ 计时脚本（10 分钟法）

> **用途**：判据 ①「**陌生人** 10 分钟内产出第一份积分」和 ③「陌生人一条命令起节点」**定义就是真人计时**。
> **执行者：人**（拉一个**从没接触过本项目**的人）。**记录，别帮忙。**
> **配套**：`status-map.md` §1、`MVP.md §11`、`mvp2-launch-readiness.md`。

---

## 0. 规则（否则计时无效）

1. **受试者是真陌生人** —— 没用过、没读过本项目文档。
2. **只给一条命令 / 一个网址**，其余**不说**。
3. **不帮忙**。他卡住就**记下卡在哪**，不是替他做。**卡点就是产出**。
4. **秒表从他看到命令开始**，到他"看到自己的分/看到节点起来"为止。
5. 判据原文要求"**全程无人工协助**" —— 你开口一次，这次就不算过。

---

## 1. 判据 ① —— 陌生人出分（目标 ≤10 min）

**给他**（先确认你已 `npm publish`，否则用本地二进制；见 `release-checklist.md`）：

```bash
npx relayfirst@latest status
```

> **⚠️ 当前现实（诚实）**：判据 ① 的完整路径需要**身份**。今天 `init` 未实现（双重阻塞），
> 所以**你要先给他一个测试密钥**（或教他 `export RELAYFIRST_PRIVATE_KEY=…`）—— **这一步算不算"人工协助"，你要自己判**。
> 若不接受，则**判据 ① 在 `init` 解阻前无法干净通过**（这正是 registration flow 是基础线的原因）。
> 同理"**产出第一份积分**"需要 `mine` 有 `--source` 与（真实 provider 时）`--api-key`。

**完整可跑路径（今天，BYO key）**：

```bash
export RELAYFIRST_PRIVATE_KEY=0x<你给的测试密钥>   # ← 可能的"协助"
relayfirst config set provider local
relayfirst mine --once --source https://example.com
relayfirst status                                  # ← 他看到的第一份分
```

**记录表**：

| 步 | 他做了什么 | 卡住？ | 秒 | 笔记 |
|---|---|---|---|---|
| 看到命令 | | | 0 | |
| 装/跑 npx | | | | |
| 设 key | | | | |
| `mine --once` | | | | |
| 看到分 | | | | **总时** |

**通过条件**：总时 ≤ **10:00**，**且你未开口指点**。

---

## 2. 判据 ③ —— 一条命令起节点（目标 ≤10 min）

**给他**（需先发镜像；见 `release-checklist.md`）：

```bash
docker run -d --name relayfirst-node -p 8080:8080 \
  -v relayfirst-data:/data relayfirst/node:latest
```

**记录表**：

| 步 | 他做了什么 | 卡住？ | 秒 |
|---|---|---|---|
| 看到命令 | | | 0 |
| docker 起容器 | | | |
| 看到节点在跑 | | | **总时** |

**验证节点起来**：`curl http://localhost:8080/healthz` 应为 200。

**通过条件**：≤ **10:00**，无协助，**无注册/许可**（MVP 硬要求）。

---

## 3. 记录在哪里

测完**如实写进** `docs/stages/S6-report.md`（或新建一节），**附**：受试者背景（"没用过"）、总时、**卡点原话**、是否协助。
**卡点是给产品的，不是给受试者的** —— 每一处卡顿都是一条待修项。

> **判据① 若因 `init` 阻塞而需协助** → **不算过**，如实标 `🟡 待 init 解阻`。别粉饰。
