# ADR-0001: EIP-712 自研薄层 vs 接入 `apitypes`

- 状态：accepted
- 日期：2026-10-04
- 影响层级：L3（实现选型；不改范围）

---

## 背景

`TASKS.md` S1-4 把选择摆成二选一：**实现 EIP-712 `hashStruct`** 或 **接入 `apitypes`**。
`MVP.md` §8 也把它列为"二选一，都行"。

这个决定之所以值得一份 ADR，是因为它**不可逆且影响多个 stage**（S1 的签名、S7 的 Merkle 域、
以及未来任何需要复算 EIP-712 摘要的地方），且它是**唯一一处我们刻意不引入成熟库的地方** ——
在 `A1`（密码学原语绝不手写）的语境下，这个决定必须留下书面理由，否则下一个接手的人会
合理地怀疑它违反了 A1。

### 先澄清：这不违反 A1

**A1 管的是密码学原语**：keccak256、secp256k1、`ecrecover`、X25519。

本 ADR 管的是**编码层**：把结构化数据按 EIP-712 的规则序列化成待哈希的字节。
keccak256 来自 `golang.org/x/crypto/sha3`，`ecrecover` 与 secp256k1 来自
`decred/dcrd/dcrec/secp256k1/v4` —— **两者都是库**，一行都没手写。

`internal/eip712/` 里没有任何曲线运算、没有模幂、没有点压缩。
它做的是 `abi.encode` 语义（`address` 左补零、`bytes32` 定长、`string` 变长带长度前缀）
加 EIP-712 的类型哈希拼装。这是**编码**，不是**原语**。

---

## 决定

**自研薄层**（`internal/eip712/`），不接入 `go-ethereum` 的 `apitypes`。

---

## 备选与取舍

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A. 自研薄层（采用）** | 无 `go-ethereum` 依赖树；只做 `abi.encode` 子集；KAT 向量锁死正确性 | 编码逻辑需自己写对（**由 KAT 承担**，见下） |
| B. 接入 `apitypes` | 复用经过实战的编码实现 | 拖入 `go-ethereum`（重）；引入 `CGO` 风险（**违反 A3**）；依赖树膨胀 |
| C. 接入其他轻量 EIP-712 库 | 比 B 轻 | 仍引入第三方；而**正确性仍需 KAT 证明**，等于没省掉关键工作 |

### 为什么 B 的"复用成熟实现"在**这里**不是决定性的

EIP-712 的正确性**不能用"用了库"来保证**。真正的保证是**跨语言一致性**：
TS 侧（viem）与 Go 侧对同一输入必须得出**逐字节相同**的哈希。

如果做不到这一点，用库也会在半年后炸 —— 而**做到这一点靠的是 KAT 向量**，
与实现来自哪里无关。换句话说：

> **有 KAT，自研与用库的差别只剩约 200 行；
> 没有 KAT，用库也会漂移。**

这正是 `HANDOFF.md` §6.3 已经写下的判断。所以"用库更安全"在这里是个**错觉**：
它只是把风险从"编码写错"换成了"依赖行为变更且无人察觉"。

### 关于 CGO（A3）

`go-ethereum` 的依赖树包含可能引入 CGO 的组件。本项目 `CGO_ENABLED=0` 是硬约束（A3），
因为它是 `docker run` 一行起节点的前提。选择 B 需要**逐项核实**整棵依赖树在 `CGO_ENABLED=0`
下可构建 —— 这是持续的维护负担，而收益（省下编码逻辑）已被 KAT 抵消。

---

## 后果

### 不可逆的部分

- `internal/eip712/` 成为**签名载荷形状的唯一权威**。S7 的 Merkle 域分离与它共享
  "域分离"这一设计习惯，但**不共享代码**（Merkle 用 `0x00`/`0x01` 前缀，EIP-712 用类型哈希）。
- 未来若新增回执字段，**必须同时**更新：`Receipt` struct、canonical JSON、
  EIP-712 typehash、以及 `testdata/eip712-vectors.json`。漏掉任一处，KAT 门禁会失败 ——
  这正是它该做的。
- 若将来有人想换成 `apitypes`，**KAT 向量会立刻判定这次替换是否等价**（逐字节比对）。
  所以这个决定是**可逆的**，代价只是重跑 KAT —— 这也是选择 A 的风险被压住的原因。

### 对 `TASKS.md` 的影响

- `S1-4` 记为 `done`，理由见本 ADR。
- `S1-5`/`S1-6`/`S1-7`（KAT 向量 + viem 基准 + Go 对齐）**不是可选项** ——
  它们是本决定成立的**前提**，不是附属品。

## 证据

跨语言一致性由 CI 门禁强制（`scripts/ci.sh`）：

```
TestKAT_Vectors                 → 10/10 PASS（viem 基准，逐字节比对）
testdata/eip712-vectors.json    → 53 向量（含 domain / message / digest 三级）
```

一致性覆盖的边界（诚实声明）：

- KAT 覆盖**编码与摘要**，即"同一结构 → 同一 digest"。
- KAT **不**覆盖：签名可延展性（已由 `sign_test.go` 的篡改测试覆盖）、
  链上 `ecrecover` 的 gas 行为（不适用，本项目不发交易）。

相关不变式：

- **A1**（密码学原语绝不手写）—— 本决定**不违反**：原语全用库，见上"先澄清"。
- **A3**（`CGO_ENABLED=0` 必须可构建）—— 本决定**支持**它：避开 `go-ethereum` 依赖树。
- **A4**（跨语言 KAT 必须在 CI 门禁中）—— 本决定**依赖**它：KAT 是正确性的唯一来源。
