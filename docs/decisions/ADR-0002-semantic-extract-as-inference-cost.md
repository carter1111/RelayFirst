# ADR-0002: 语义化 extract 作为推理成本的载体

- 状态：accepted
- 日期：2026-10-03
- 影响层级：L0

---

## 背景

`MVP.md` §1.3 的核心洞察是：**用户手上被忽略的稀缺资源是 agent 订阅的推理额度**，
并据此推出"自限"—— 农民被自己的账单限制，因此不需要复杂反女巫规则。

S2 实现完成后发现一个断层（完整证据见 [`docs/notes/inference-cost-gap.md`](../notes/inference-cost-gap.md)）：

三个 executor（`probe` / `extract` / `compute`）**全是确定性的网络或 CPU 操作，不调用任何 LLM**。
`work.Provider` 只是从 spec 抄来的字符串，`TokensIn` / `TokensOut` 恒为 0。

后果不是"少个 provider"，而是**成本为零**：

- §1.3 的「稀缺 / 有真实成本 / 自限」三行**全部不成立**。
- 抗女巫的第一层（全局去重）仍有效，但它只**迫使攻击者更换 URL** ——
  一个 curl 脚本即可零成本刷满全网。
- §5.0 之所以能拒绝 `fetch + 任意 hash`，是因为当时假设**推理质量是工作量的来源**；
  剥掉推理后，`probe` / `extract` 就退化成了被拒绝的那种任务，只是多了个字段名。

**叙事说"你的订阅是矿机"，但矿机不烧油。**

---

## 决定

**`extract` 的字段声明，除 dot-path 外，允许自然语言描述**
（例如 `"主要商品价格"` 而非 `data.price`）。

在一个不熟悉的、结构混乱的页面上解析自然语言字段，**经济上需要一次 LLM 调用**，
从而真实消耗 token。

### 三条同时守住的边界

1. **结果仍是确定性规范化字符串。**
   归一化规则固定（数字→十进制、文本→trim、缺失→`null`），
   因此验证仍是**二值**（对/错），**不引入争议层**。

2. **§5.0 的红线不破。**
   仍**拒绝**生成类任务（无 ground truth）与「取任意 URL + hash」（只证明取过）。

3. **可验证性优先于成本。**
   若某任务的正确性需要"质量"判断，它就**不属于** `extract`，应被**拒绝** ——
   而不是放宽判定标准。这条是 §5.0 的地基，不得为省事而软化。

---

## 备选与取舍

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A. 语义化 extract（采用）** | 保住 §5.0 的二值验证；成本真实；不新增任务类型 | 成本**诱导**而非强制，可被机械规则绕开 |
| B. 改叙事为"数据采集网络"，用押金/白名单做稀缺 | 不依赖 LLM | **放弃**"订阅挖矿"核心卖点；需重写 §1.3 与 §10.1 |
| C. 只接 S2-6（BYO API key），任务不变 | 改动最小 | **不解决**问题 —— 任务本身不需要推理 |
| D. 引入生成类任务 + 验证层 | 成本最真实 | **破坏 §5.0**，必然引入争议层 → 复杂度爆炸 |

选 A：它是在**不破坏二值验证**的前提下，唯一能让成本真实的方案。

---

## 后果

### 不可逆的部分

- `extract` 的 spec schema 增加语义化形式；实现需支持 LLM 调用路径。
- **`S2-6`（BYO API key）从"可选补全"上升为承重项** —— 没有它，语义化任务无法执行。
- 新增对 LLM provider 的运行时依赖（此前 S1/S2/S3 均无外部服务依赖）。
- 可能触及 `MVP.md` §8 的"无 CGO / 纯 Go"边界：LLM 调用是 HTTP，**不违反**；但需确认选型。

### 对 `TASKS.md` 的影响

- `S2-6` 重新定位为**承重项**。
- 新增 `S2-9`（语义化 extract 实现）。
- `S2-8`（SQLite）优先级不因此改变，但语义化任务的回执更需要持久化（token 计量要可审计）。

### 必须保留的诚实声明（AI 不得删改）

> 本 ADR 引入的成本是**经济诱导**的，**不是协议强制**的。
> 决心机械解析的攻击者**仍可写规则绕开** LLM。
> 抗女巫的**主要承重**仍是全局去重（迫使不断更换 URL），
> 语义化只**抬高**成本。**不得对外表述为"不可绕过"。**

这与 `MVP.md` §5.6 对 sybil 防御的诚实要求一致：把有洞的机制包装成无洞，被拆穿一次叙事就没了。

### 若 BLK-1 被证伪

若"订阅无法程序化驱动"成立，语义化任务**仍可用 BYO API key 执行**。
叙事退化为"用自己的 API 额度挖矿"，但**不影响技术上的可验证性** ——
这是本方案相对选项 B 的额外好处：它不把技术架构绑死在订阅这件事上。

---

## 证据

断层由代码检索确认（2026-10-03）：

```
$ rg -i 'openai|anthropic|llm|inference|completion' internal/mining/
loop.go:196  // providerOf ... defaulting to "local" for tasks that need no inference
loop.go:200  // compute tasks genuinely consume no inference budget

$ rg 'TokensIn|TokensOut' internal/mining/loop.go
# 无赋值处 —— 两个字段永远是零值
```

相关不变式：

- **A2**（任务类型约束）—— 本决定**不放宽**它，只是改变了 `extract` 的字段表达形式。
- **A6**（全局去重必须保持承重地位）—— 本决定明确**不取代**它，见上方诚实声明。
